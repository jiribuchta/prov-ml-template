🔗 Every run is pinned

A step consumes exactly the run you pinned — never “the latest”. Every step prints the [hint] line to paste, so a config always names the exact dataset and runs it used.

📍 Data stays in place

Files stay where Adam put them — nothing is copied. Only manifest.csv is written into data_path.

🧪 Verification is automatic

split_dataset checks your disk against Adam's fingerprint and tags the run dataset_verified — you can't silently analyse changed data.

ADAM  PREREQUISITE Register the dataset — once per version

Expected of Adam, needed by everyone — no analysis can run before it.

Data is on the cluster — any file type (.mrxs, .svs…), any folder shape.
Copy an experiment YAML and fill in the three data things: 
data_path: /mnt/data/.../mammaprint
pipeline:
  pattern: '.*\.mrxs$'   # how to find the samples
dataset:
  name: mammaprint        # + version
Run one command — manifest is built, fingerprint stored: 
$ uv run python -m pipeline pipeline=register_dataset \
        +experiment=mammaprint
[hint] ... dataset.run_id=f94f159b…
Hand it over — commit the YAML to git, send the user the run_id.

What it needs → what it produces

needs: the data on the cluster + 3 YAML entries — data_path, pattern/source, name+version

produces: manifest.csv · a Dataset_Registry run with the dataset fingerprint (file sizes + mtimes) · the run_id he sends you

Three ways to point at the samples

📊 Cohort table — the csv/xlsx that ships with the data:
source: cohort.xlsx + path_column / label_column

🔎 Regex — folder + “what to find”: pattern: '.*\.mrxs$'
label = named group (?P<label>…) or parent folder · recursive

🌳 Folders — one subfolder per class, any file type

🔁 New data version? Same steps, bump version — the old registration stays, old runs stay reproducible.

YOU  PREREQUISITE Register yourself — once, ever

The one thing expected of you before your first analysis — takes a minute.

terminal
# 1. create the environment
$ uv sync

# 2. point at your MLflow server
$ export MLFLOW_TRACKING_URI=...
terminal
# 3. register yourself — once, ever
$ uv run python -m pipeline \
      pipeline=create_user +experiment=mammaprint

[create_user] registered 'jiri-buchta' → User_Registry

Username is automatic — the same one kube-jobs uses (JOB_USER / kube config), so your cluster runs link to you without any setup.

needs: uv + the MLflow server address — no data, no YAML, nothing else
produces: one run in User_Registry — every run you ever start is linked to you

YOU  The pipeline — run an analysis, the exact loop

Prerequisites done — this is the part you repeat for every analysis.

terminal
# 1. paste the run_id Adam sent you into mammaprint.yaml, then:
$ uv run python -m pipeline pipeline=split_dataset +experiment=mammaprint
[hint] dataset.mlflow_uris.split_dataset=runs:/…/train.csv

# 2. paste that line into the yaml (mlflow_uris), then:
$ uv run python -m pipeline pipeline=embed_dataset +experiment=mammaprint
[hint] dataset.mlflow_uris.embed_dataset=runs:/…/embeddings/train.csv

# 3. paste that line into the yaml, then:
$ uv run python -m pipeline pipeline=learn +experiment=mammaprint
[learn] ARI vs ground truth = 1.000

That's the whole job

▶ run a step

▼ copy its printed [hint] line

▼ paste it into configs/experiment/mammaprint.yaml

▶ run the next step

✅ Forgot to paste? The step fails immediately and prints exactly what is missing — nothing is guessed, nothing runs on the wrong data.

🔁 Rerun any step any time — the pins decide what it consumes, not the order you ran things in.

YOU  The pipeline on the cluster — one job per step

terminal
# once: set EXPERIMENT = "mammaprint" in scripts/_submit.py
$ uv run python scripts/split_dataset.py   → k8s job
$ uv run python scripts/embed_dataset.py   → k8s job
$ uv run python scripts/learn.py           → k8s job

Same paste-the-pin loop, same YAML — the job just runs the command for you. Jobs record job_* tags (cluster, CPU/memory, image). (Adam has scripts/register_dataset.py for his one-time part.)

terminal
# or the whole chain in one job:
$ uv run python scripts/submit_pipeline.py

🔗 The chain job forwards the pins itself — each step's printed [hint] line is passed to the next command, so you don't paste anything for a full fresh run.

👤 Username comes from your kube config — create_user once locally and the jobs link to you automatically.

🧪 machine-learning — mlkit only

ml/__main__.py — real template code
@hydra.main(config_path="../configs", config_name="project_name")
@autolog
def main(config, logger: MLFlowLogger):
    seed_everything(config.seed, workers=True)
    data = hydra.utils.instantiate(config.data, ...)
    model = hydra.utils.instantiate(config.model, _target_=MetaArch)
    trainer = hydra.utils.instantiate(config.trainer,
                                      _target_=Trainer, logger=logger)
    getattr(trainer, config.mode)(model, datamodule=data)

To trace runs like provenance does, you would write — by hand, every run:

mlflow.set_tag("git_commit", ...)      ❌ forget it once, lose the link
mlflow.log_param("data_path", ...)     ❌ a path string — not the files
mlflow.log_artifact("requirements.txt") ❌ hope it's the right env
❌ no user identity · no dataset fingerprint · nothing
   verifies the disk · runs don't know their upstream

🧬 this template — mlkit + provenance

pipeline/__main__.py — real template code
@hydra.main(config_path="../configs", config_name="pipeline")
@autolog
def main(config, logger: MLFlowLogger):
    mlflow.set_tag("step", config.pipeline.step)
    _STEPS[...](config, logger)

# inside every step — the whole change is this one call:
log_provenance(config=config)   # user · dataset fingerprint
                                # git commit · image · hardware
                                # seeds · upstream inputs

…plus one block in the same experiment YAML:

pipeline:
  pattern: '.*\.mrxs$'   # where the samples come from
dataset:
  name: mammaprint       # registered + verified
  version: 1.0.0
  run_id: f94f159b…      # Adam's registration
  mlflow_uris:        # the pins you paste

Nothing else changes: same @hydra.main + @autolog + MLFlowLogger · same configs/experiment/*.yaml · same uv run python -m … +experiment=… · same kube-jobs — Adam's one-time register_dataset and your one-time create_user fill the registries.
