PART 2 · PROVENANCEhow it works

Three kinds of run answer three questions

👤 user run — who

One per person (create_user, once ever) in the User_Registry experiment. Your kube username is the key — every run you start is linked to you.

🗂️ dataset registration run — what data

One per dataset version (register_dataset, run by whoever brings the data) — in the project's experiment: the fingerprint — file sizes + mtimes — that later steps verify your disk against.

▶ pipeline runs — what happened

One MLflow run per step — same experiment: user, git commit, docker image, hardware, seeds, upstream inputs, output artifacts — chained by pinned URIs.

your mlkit trainer config — the whole provenance setup
trainer:
  callbacks:
    - _target_: rationai.mlkit.lightning.callbacks.ProvenanceCallback
      fail_fast: true        # abort if disk ≠ fingerprint
      split_uris: …       # your split run — chains + verifies

Zero provenance code — the callback logs user · dataset fingerprint · git commit · image · hardware · seeds · upstream inputs.

🏛️ From these runs, a W3C PROV document can be assembled — who ran what, on which data, with which code and environment.

PART 2 · PROVENANCEthe three rules

What makes it trustworthy

🔎 The disk is verified

split_dataset re-walks the folder and checks every file against the registration fingerprint → tags the run dataset_verified. Changed files since registration? You see it, not silently analyse it.

📌 Nothing resolves implicitly

A step consumes exactly the run pinned in its config — never "the latest". A missing pin fails immediately and prints the [hint] line to paste. Old runs stay reproducible.

📍 Data is used in place

Files stay where they are — nothing is copied or moved. Only manifest.csv is written into the folder; splits are lists of files, logged as small CSV artifacts.

▶ what one run records

tagsstep · dataset_verified · git commit · docker image · hardware · seeds · job_* paramsthe whole resolved Hydra config (cfg_*) artifactstrain/test.csv · embeddings/ · cluster/ · frozen requirements · console.log inputsinput_uris → the upstream run it consumed

🧪 Verification failure aborts? In the pipeline steps it tags dataset_verified=False and continues; in mlkit training (ProvenanceCallback + split_uris) the split run is followed to its registration and the disk re-checked — fail_fast: true aborts.

PART 3 · YOUR WORKFLOWprerequisite — anyone with data

PREREQUISITE · ANYONE WITH DATA Register the dataset — once per version

Done by whoever brings the dataset — no analysis can run before it.

Data is on the cluster — any file type (.mrxs, .svs…), any folder shape.
Run one command — no YAML, the values go inline: 
$ uv run python -m pipeline pipeline=register_dataset \
      metadata.experiment_name=Mammaprint \
      data_path=/mnt/data/.../mammaprint \
      pipeline.source=slides.csv dataset.name=mammaprint
[hint] ... dataset.run_id=f94f159b…
Manifest built, fingerprint stored — the registration run in the project's experiment records the path, the csv, name + version.
Share it — hand the run_id to whoever analyses; the run itself records the rest.

What it needs → what it produces

needs: the data on the cluster + three values — data_path, the csv with the slide paths (pipeline.source), dataset.name · version defaults to 1.0.0

produces: manifest.csv · a registration run in the project's experiment with the dataset fingerprint (file sizes + mtimes) · the run_id to share

The csv with the slide paths

📊 usually the cohort table that ships with the data — a path / slide / wsi_path column (or the only column) holds the paths, an optional label / cancer column the classes

📁 paths absolute or relative to data_path — missing files fail the step · registered in place, nothing copied

PART 3 · YOUR WORKFLOWper analysis · step 1

YOU  Split the dataset — one command

terminal
# 1. paste the dataset's run_id (from its registration) into configs/experiment/mammaprint.yaml:
dataset:
  run_id: f94f159b…      # the registration — the pin

# 2. run the split — the only pipeline command you need for training:
$ uv run python -m pipeline pipeline=split_dataset +experiment=mammaprint
[hint] dataset.mlflow_uris.split_dataset=runs:/6b2c…/train.csv

☁️ Same on the cluster (part 1): the same step as a kube-job — same pin, same YAML. 🔁 Rerun any time — the pin decides, not the order.

What that one command did

🔎 Verified the disk against the registration fingerprint → dataset_verified tag

📄 train.csv / test.csv — lists of files, logged as small artifacts — data stays in place

📌 printed the [hint] — your splits now live in a run you can point training at

🧬 The template also ships demo embed_dataset / learn steps — placeholders for your own preprocessing. For training on the splits you only need split_dataset.

PART 3 · YOUR WORKFLOWper analysis · step 2 — the main one

Train on the splits with mlkit — zero provenance code

🧠 your mlkit app — not one line changes

ml/__main__.py — your existing mlkit main
@hydra.main(config_path="../configs", config_name="project_name")
@autolog
def main(config, logger: MLFlowLogger):
    seed_everything(config.seed, workers=True)
    data = hydra.utils.instantiate(config.data, ...)
    model = hydra.utils.instantiate(config.model, _target_=MetaArch)
    trainer = hydra.utils.instantiate(config.trainer,
                                      _target_=Trainer, logger=logger)
    getattr(trainer, config.mode)(model, datamodule=data)

Provenance like this, you would write by hand, every run:

mlflow.set_tag("git_commit", ...)       ❌ forget it once, lose the link
mlflow.log_param("data_path", ...)      ❌ a path string — not the files
❌ no user identity · no fingerprint · nothing verifies the disk

➕ the whole addition — one block in the trainer config

configs/experiment/<project>.yaml — trainer section
trainer:
  callbacks:
    - _target_: rationai.mlkit.lightning.callbacks.ProvenanceCallback
      fail_fast: true             # abort if disk ≠ fingerprint
      split_uris:                # ← point at your split run
        train: <split run artifact_uri>/train.csv
        test:  <split run artifact_uri>/test.csv

That block logs user · dataset fingerprint · git commit · docker image · hardware · seeds · input_uris — your training run chains to the split run and re-verifies the data on disk against its registration; nothing is re-split or copied, fail_fast aborts on a broken dataset.

⚠️ URI form: use the split run's artifact_uri (MLflow UI, or mlflow.get_run(...).info.artifact_uri) — not the runs:/… form the [hint] prints.

Same @hydra.main + @autolog + MLFlowLogger as the mlkit template — the callback is the only difference, and it is config, not code.
